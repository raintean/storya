# 提交规范

准备提交或推送 Storya 改动时遵守以下规则:

- 执行 `git commit` 或 `git push` 前，先向用户说明准备提交或推送的内容并取得明确授权。
- 提交信息格式为 `<type>: <简体中文说明>`，例如 `feat: 建立项目基础骨架`。
- 常用类型包括 `feat`、`fix`、`refactor`、`docs`、`test`、`build`、`ci` 和 `chore`。
- 类型后不添加 `(模块)` scope。
- 不添加 `Co-authored-by`、AI 署名或其他协同作者信息。
- 一个提交只包含一个逻辑目标，不把无关修改混在一起。
- 提交前检查暂存内容，并运行与改动范围相称的格式检查、lint、静态检查和测试。
